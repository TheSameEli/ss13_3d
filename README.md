# SS13 First Person — экспериментальный рендерер для BandaStation

Вид от первого лица для Space Station 13 внутри настоящего BYOND DreamSeeker. Мод превращает доступную клиенту 2D-сцену в перспективное пространство: пол и стены получают геометрию, часть мебели и машинерии — объём, персонажи и многие предметы остаются спрайтами.

**Создатель проекта — [TheSameEli](https://www.twitch.tv/thesameeli).** См. [AUTHORS.md](AUTHORS.md).

Проект разрабатывается и проверяется на **[BandaStation / SS220](https://github.com/ss220club/Bandastation)**. Он использует ресурсы этой сборки и её устройство слоёв. Это отдельный экспериментальный клиентский мод, а не официальный клиент BandaStation, не самостоятельная игра и не замена DreamSeeker.

**Статус: рабочий прототип.** Пользовательские игровые проверки были положительными, однако некоторые классы объектов и действия всё ещё имеют ошибки. Полной совместимости со всеми картами, объектами и серверами нет. [Известные проблемы и ограничения](docs/KNOWN_ISSUES.md) — часть описания текущего состояния, а не список уже исправленного.

## Зачем

Посмотреть на станцию изнутри, сохранив игровые механики SS13, исходные пиксельные ресурсы и штатный интерфейс. Сервер продолжает управлять перемещением, доступом, столкновениями и взаимодействием. Мод меняет представление сцены и преобразует ввод для камеры от первого лица.

Это не полноценный 3D-порт: серверный мир остаётся тайловым и двумерным на каждом Z-уровне, а объём восстанавливается на клиенте по спрайтам и эвристикам.

## Совместимость

| Компонент | Поддержка |
| --- | --- |
| ОС | Windows x64; запускаемый DreamSeeker и мод — **x86** |
| BYOND | **516.1688**, только три бинарных файла с SHA-256 из [compatibility.json](compatibility.json) |
| Графика | Аппаратный Direct3D 9 DreamSeeker; программный рендерер не поддерживается |
| Игровая сборка | BandaStation; точка отсчёта локальных ресурсов указана в `compatibility.json` |
| Другие SS13-сборки | Не проверены; имена ресурсов, плоскости и слои могут отличаться |
| Linux, macOS, Wine, другие версии BYOND | Поддержка не заявлена |
| Сервер | Обычный сервер BandaStation, без серверных модификаций для этого клиента |

Номер версии сам по себе недостаточен: launcher сравнивает содержимое `dreamseeker.exe`, `byondcore.dll`, `byondwin.dll`. После обновления BYOND потребуется заново проверить ABI и перенести перехваты. **Не заменяйте контрольные суммы просто ради обхода проверки.**

## Как устроен запуск

`Start-Mod.cmd` вызывает PowerShell-проверку совместимости, запускает **новый** DreamSeeker и загружает DLL только в созданный процесс через `LoadLibraryW`. Мод читает уже полученную клиентом сцену и использует его D3D9 device для отрисовки. Сетевое подключение, загрузка ресурсов, чат, HUD и игровые команды остаются в BYOND.

DLL устанавливает перехваты импорта и функций рендерера в памяти процесса. Файлы установленного BYOND не патчатся. Загрузка мода не отключает проверки сервера и не даёт серверных прав. Возможность использования такого клиента на публичном сервере нужно согласовать с его администрацией; проект этого разрешения не подразумевает.

## Установка и запуск

Исходный репозиторий не содержит готовых бинарников BYOND, игрового сервера, музыки или сгенерированных текстур. Для первого запуска соберите мод по разделу ниже либо используйте подготовленный проверенный релиз.

1. Установите поддерживаемый BYOND и получите собранные `bin/launch.exe`, `bin/scene_probe.dll`.
2. Запустите сервер BandaStation отдельно. Локальный адрес по умолчанию — `byond://127.0.0.1:1337`.
3. Из каталога мода выполните:

```powershell
.\Start-Mod.cmd
# Другой сервер или другая папка BYOND:
.\Start-Mod.cmd -Server byond://127.0.0.1:1337 -ByondBin 'D:\BYOND\bin'
# Только проверка бинарников, без запуска клиента:
.\Start-NativeClient.ps1 -CheckOnly
```

4. Войдите в игру обычным способом, нажмите F8 и щёлкните по игровому миру для захвата мыши.

Обычный ярлык DreamSeeker не загружает мод. Нужен запуск через `Start-Mod.cmd` или ярлык именно на этот скрипт. Сервер эти скрипты не запускают. При ошибке загрузки DLL новый DreamSeeker может остаться работающим в обычном режиме: сообщение о запуске процесса не доказывает работу рендерера.

## Управление

| Действие | Управление |
| --- | --- |
| Штатный 2D ↔ первое лицо | **F8**; прежний объёмный вид сверху убран из переключателя |
| Захват взгляда | ЛКМ по миру; этот первый клик не выполняет игровое действие |
| Освободить мышь | Tab или Esc; можно работать с чатом, HUD и меню |
| Взгляд | Мышь при захвате |
| Движение | WASD относительно камеры, с округлением до направлений серверной сетки |
| Взаимодействие | ЛКМ/ПКМ по прицелу; игровые правила и модификаторы обрабатывает BYOND |
| Тащить объект | Ctrl+ЛКМ; поддержка зависит от конкретного действия и доступности цели |
| Перенос между целями | Удерживать ЛКМ, навести на цель, отпустить; регрессии ещё возможны |
| Смена руки | Колесо мыши, через штатную привязку X |

При свободном курсоре ввод возвращается штатному клиенту, а направление движения может отличаться от направления камеры. Названия целей запрашиваются через нативный hover; они не генерируются по картинке. Не все случаи клика через стекло, перетаскивания, контейнеров и HUD подтверждены игровыми проверками.

## Что меняется в отрисовке

| Элемент | Представление |
| --- | --- |
| Пол, трубы, кабели, ленты | Горизонтальные поверхности; площадки лифтов тоже распознаются как пол |
| Стены, стекло, решётки | Объёмные/тонкие панели; у стекла отдельный проход прозрачности |
| Шлюзы | Направленные панели, специальные варианты для двойных шлюзов и windoor / strong door |
| Открытые двери | Направляющие и стойки вместо растянутого закрытого полотна; варианты ресурсов могут требовать отдельных правил |
| Мебель и машинерия | Процедурная геометрия по классу и непрозрачному контуру, а не полноценные авторские модели |
| Обычные стулья | Вертикальные 2D-спрайты; кресла и диваны сохраняют объём |
| Персонажи и свободные предметы | Спрайты, обращённые к камере; мелкие предметы уменьшены |
| Зарядник | Плоский спрайт с учётом поверхности стола |
| Настенные приборы | Привязка к ближайшей подходящей стене, высота по классу устройства |
| Потолки | Добавляются эвристически; низкие в помещениях, высокие над распознанными пещерами |
| Космос | Далёкий фон из ресурсов parallax, включая верх/низ; это фон, не крыша и пол |
| Лава | Опущенная горизонтальная поверхность, усиленное свечение и отдельная анимация |
| Освещение и даль | Нативная карта света плюс локальная обработка, чёрный туман у границ доступной сцены |
| Миникарта | Север сверху, ширина около **22%** области рендеринга; только доступные клиенту данные |
| Предмет в руке | Экранное представление для первого лица, не отдельная 3D-модель оружия |

Полный перечень правил, размеров, искусственных изменений и исключений: [RENDERING.md](docs/RENDERING.md).

## Ограничения, которые стоит знать до игры

- Клиент не получает полную карту. За пределами полученной сцены могут быть пустота, туман и пропавшие объекты; миникарта тоже неполная.
- Визуальная геометрия не является серверной коллизией. Видимый край лавы, двери, шкафа или прохода может не совпадать с действующей областью тайла. Опасности определяет сервер.
- Классы восстанавливаются по DMI-кадрам, альфа-силуэтам, слоям и соседям. Новые или одинаковые текстуры, перекраска, нестандартные трансформации и сложные оверлеи могут ошибочно распознаться.
- Вложенное стекло, открытые двери, настенные надписи и содержимое шкафов остаются зонами риска. Исправленные тесты не означают, что все варианты уже проверены в игре.
- **Анимация работающих конвейеров пока не исправлена.** Анимации исходных DMI в целом не гарантированы. Отдельная анимация лавы не решает эту общую проблему.
- Зеркала не рендерят полноценное отражение сцены. Свет, потолки, пещеры и высота между уровнями приближённые; это не физически корректный рендерер.
- Полная поддержка эффектов BYOND, всех MouseParams/drag-сценариев, смены устройства D3D и горячей выгрузки DLL не реализована.
- Дополнительные проходы, чтение световой поверхности и сборка геометрии стоят CPU/GPU-времени. Обещанного FPS или подтверждённой минимальной видеокарты нет.

Описание воспроизведения ошибок и их статусы: [KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md). Подробности совместимости и внутренних перехватов: [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Сервер и звук

Мод полностью клиентский: серверное дополнение и собственное воспроизведение музыки удалены. Для отрисовки не требуется добавлять DM-файлы или команды OOC. Штатные звуки игры остаются под управлением DreamSeeker.

## Сборка из исходников

Нужны Windows x64, Visual Studio 2022 C++ Build Tools с Windows SDK, Python 3.10+ и Pillow. Используется 64-битный хост компилятора с целевой архитектурой **x86**: объём сгенерированных ресурсов может исчерпать память 32-битного компилятора.

Получите отдельную копию [BandaStation](https://github.com/ss220club/Bandastation). Для воспроизведения текущих правил исходный commit указан в `compatibility.json`. Локальные изменения этого рабочего дерева в manifest не включены; commit — ориентир ресурсов, а не гарантия побайтовой воспроизводимости сервера.

```powershell
python -m pip install -r requirements.txt
$env:BANDASTATION_ROOT = 'D:\src\BandaStation'
.\build.cmd
.\check_first_person.cmd
python .\check_asset_geometry.py --assets-root $env:BANDASTATION_ROOT
```

`build.cmd` создаёт `*.generated.h` из исходных ресурсов и собирает DLL/launcher в `bin`. `build.cmd --code-only` допускается только при уже существующих актуальных заголовках. `BANDASTATION_ROOT` не требуется, если мод расположен как `BandaStation/native_client`.

Подробности зависимостей, проверок, ABI-порта и подготовки отдельного репозитория: [DEVELOPMENT.md](docs/DEVELOPMENT.md). Результаты ревью: [REVIEW.md](docs/REVIEW.md).
