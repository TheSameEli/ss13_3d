# Разработка, проверки и выпуск

## Среда и воспроизводимость

Нужны Windows x64, Python 3.10+, Pillow из `requirements.txt`, Visual Studio 2022 C++ Build Tools и Windows SDK. `msvc-env.cmd` ищет установленный компилятор через `vswhere`. При нестандартной установке задайте `BS220_VCVARS` полным путём к `vcvarsamd64_x86.bat`. Нужен **64-битный compiler host для x86 target**, а не DLL x64.

```powershell
python -m pip install -r requirements.txt
$env:BANDASTATION_ROOT = 'D:\src\BandaStation'
python .\compile_geometry.py --assets-root $env:BANDASTATION_ROOT
.\build.cmd --code-only
.\check_first_person.cmd
python .\check_asset_geometry.py --assets-root $env:BANDASTATION_ROOT
python .\test_tools.py
```

Либо `build.cmd` выполнит генерацию перед C++-сборкой. Генератор проверяет наличие обеих папок ресурсов и пишет результат рядом со своим скриптом; он не должен писать в чужое дерево BandaStation. Не импортируйте генератор как библиотеку: это исполняемый CLI. Общие чистые функции находятся в `asset_utils.py`.

`compatibility.json` содержит commit, по которому готовились правила ресурсов. Рабочее дерево разработчика имело локальные изменения; этот commit не является описанием всех локальных изменений сервера. Для строгого релиза необходимо записать точный чистый commit ресурсов, версию компилятора и зависимости Python. Побайтовая воспроизводимость DLL пока не обещается.

Generated headers исключены из публичного исходного каталога. Если их нет, `--code-only` закономерно не соберётся. При изменении DMI или правил классификации запустите генерацию снова. Отсутствие нужного каталога должно давать понятную ошибку, а не пустую таблицу.

## Работа без остановки игрока

При работающем DreamSeeker загруженная DLL может быть заблокирована. Для проверки изменений собирайте в другую папку:

```powershell
$env:BS220_OUTPUT_DIR = 'bin\review'
.\build.cmd --code-only
$env:BS220_OUTPUT_DIR = 'bin\review-checks'
.\check_first_person.cmd
Remove-Item Env:BS220_OUTPUT_DIR
```

Не заменяйте используемую DLL во время игры. Для игрового прогона завершите только клиент, созданный этим launcher, положите проверенную сборку в `bin` и запустите новый клиент. Изменение исходников не обновляет код уже загруженного процесса.

## Что именно проверяется

| Проверка | Что доказывает | Чего не доказывает |
| --- | --- | --- |
| MSVC /W4 | Сборка x86, типы и предупреждения компилятора | Корректность ABI и внешний вид |
| `check_first_person.cmd` | CPU-геометрия, near clipping, alpha picking, ввод, высоты, отдельные регрессии; компиляция HLSL ps_2_0 | Установку перехватов в DreamSeeker и полный игровой раунд |
| `check_asset_geometry.py` | Совпадение конкретных исходных DMI-кадров с правилами generated header | Все варианты, серверные типы и отсутствие fingerprint-конфликтов |
| `test_tools.py` | Нормализацию прозрачных пикселей, чистый экспорт и отказ от перезаписи существующего каталога | Игровую совместимость |
| `Start-NativeClient.ps1 -CheckOnly` | SHA трёх установленных файлов BYOND | Работу графики или подключения |
| Ручной прогон | Конкретные сцены, состояния и действия | Все карты и типы объектов |

## Ручной регрессионный маршрут

1. 2D ↔ F8, захват, Tab/Esc, смена фокуса, курсор, чат и HUD.
2. Движение при поворотах камеры, короткий тап и удержание, отсутствие двойного шага, свободный курсор.
3. ЛКМ/ПКМ, hover, Ctrl+ЛКМ, перенос на пол/стол/себя/контейнер, смена руки.
4. Одинарные и двойные шлюзы в обоих направлениях, закрыто/открыто/анимация. То же для windoor и фаерлока.
5. Два стекла подряд, стекло перед дверью; сравнение с штатным 2D, клики по объектам за стеклом.
6. Лифт на остановках и в движении; пол, потолок, переходы Z.
7. Шкафы/содержимое, зарядник на столе, настенные надписи/лампы/сигнализации в четырёх направлениях.
8. Лаваленд, граница лавы и повреждение на сервере, пещера/открытая площадка, космос сверху и снизу.
9. Конвейер выключен/включён/реверс: известная незавершённая анимация должна оставаться отмеченной.
10. Сворачивание/возврат/изменение размера окна; штатный игровой звук не должен изменяться модом.

Для каждого прогона записывайте дату, commits, BYOND hashes, карту, устройство/разрешение, сценарий и результат. Не превращайте старую запись `validation.json` в доказательство новой сборки.

## Перенос на другой BYOND

Сначала изучить новые экспорты, calling convention, MapIcon stride/смещения, vtable/RVA и MouseParams. Потом обновлять `byond_abi.h`, места raw field access, декодеры, контрольные суммы и тесты. Проверить установку каждого hook по логам и визуальному состоянию. Не менять только `compatibility.json`, чтобы запустить заведомо другой бинарник.

## Стиль изменений

Предпочитать небольшие функции и именованные параметры вместо новых магических значений. Поддерживать границы: launcher/ABI, ввод, классификация ресурсов, геометрия, HLSL. Добавлять новую эвристику с исходным DMI, конкретным состоянием и тестом воспроизведения. Вынесение всего renderer из `volume.cpp` в этом проходе не делалось: это отдельная рискованная работа, требующая игровых регрессий.

При исправлении не смешивать визуальную геометрию с серверной физикой. В документации различать намеренное отличие от 2D, незавершённую функцию и подтверждённый баг.

## Подготовка отдельного GitHub-репозитория

```powershell
python .\export_source.py
```

Команда создаёт новый `publish/ss13-first-person` по явному списку файлов. Она не инициализирует Git, не пушит, не копирует сервер целиком и отказывается перезаписывать существующий каталог. Для другой выгрузки задайте `--output` новым путём. В каталоге есть `SOURCE_MANIFEST.json` с SHA-256; это список содержимого, не цифровая подпись.

Не попадают: `bin`, старые `package`, `research`, `.git`, дампы/логи, игровые конфиги, музыка, BYOND DLL/EXE, generated headers и соседние проекты. `LICENSE`, `AUTHORS.md`, `THIRD_PARTY.md` и `compatibility.json` входят; серверных дополнений нет. Инструкция описывает сборку с отдельным деревом ресурсов.

Перед публикацией нужны выбранные владелец/имя репозитория и видимость; доступ GitHub через локальную авторизацию, например `gh auth login`; автор/контакты проекта и, при желании, отображаемое название. Токены и пароли в чат не нужны. Для бинарного релиза отдельно проверить атрибуцию всех встроенных ресурсов и не включать коммерческую музыку.

## Диагностические инструменты

`decode_scene.py` читает локальный `scene.bin` и сохраняет JSON с raw hex. Он понимает только наблюдаемые форматы 208/216 байт, а не весь ABI. `inspect_live_assets.py PID` — инструмент разработчика, читающий память локального клиента с правом чтения. Требует актуального журнала этого же запуска; адреса из другого PID не подходят. Ни один инструмент не должен публиковать снятые игровые данные автоматически.
