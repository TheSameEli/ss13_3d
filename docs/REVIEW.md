# Код-ревью от 17 октября 2026

Объём: нативный клиент, launcher, генератор классификации, проверки, сценарии запуска/сборки и подготовка исходников к отдельному репозиторию. Изменения соседнего игрового сервера, AI-модулей и личных настроек не входят. Это ручное ревью; прохождение локальных проверок не является аудитом всего BYOND.

## Найдено и исправлено

| Приоритет | Находка | Исправление / проверка |
| --- | --- | --- |
| P1 | У `ScreenEdge` было неверное decorated name: `GetProcAddress` возвращал null, часть нативных смещений не учитывалась | Исправлен символ, вынесен в `byond_abi.h`; точное имя сверено с экспортами установленной DLL. Изменение размещения требует игрового прогона |
| P2 | Launcher закрывал HANDLE только на успешном пути; ошибки setup/thread/timeout оставляли дескрипторы и часть remote allocation | Owned handles переведены на `WinHandle`; память освобождается до старта потока и после его завершения. На таймауте строка намеренно живёт до выхода клиента, чтобы не освободить память работающему потоку |
| P2 | Генератор писал в `<asset-root>/native_client`, поэтому отдельный репозиторий не мог нормально собираться | `--assets-root` / `BANDASTATION_ROOT`, output рядом с генератором, проверка входных каталогов |
| P2 | Сборка знала только абсолютный путь к Build Tools на машине разработчика | Общий `msvc-env.cmd` с `vswhere`, override `BS220_VCVARS`; сохраняется x64 host → x86 target |
| P2 | Публичная выгрузка рабочего дерева могла включить музыку, приватные дампы и посторонний серверный код | Exporter по явному allowlist, `.gitignore`, отдельный clean-каталог, manifest и тест исключений |
| P2 | README смешивал старый 2.5D, старый BYOND и недоказанные утверждения о проверках | Новый README и отдельные текущие ограничения/архитектура/рендеринг. Исторический README сохранён локально в игнорируемом `research`, но не экспортируется |
| P3 | Тест импортировал функцию fingerprint через AST/exec исходного CLI | Общий `asset_utils.py`; тест и генератор импортируют одинаковую чистую функцию |
| P3 | HLSL находился одной длинной C++-строкой | Вынесен в `lighting_shader.h`, компиляция шейдера остаётся в регрессионном тесте |
| P3 | Размер MapIcon повторялся в части буферов/копирования сцены | Эти места используют `ByondAbi::mapIconStride`; оставшаяся raw-разметка ABI ещё требует типизации |
| P3 | В скриптах запуска дублировались SHA и не было безопасного режима проверки | Manifest `compatibility.json`, `-CheckOnly`, параметр пути BYOND, проверка наличия артефактов |

## Открытые технические риски

| Приоритет | Риск | Следующий шаг |
| --- | --- | --- |
| P1 | Внутренний ABI и borrowed pointers. Полный lifetime/threading protocol сцены не доказан; неправильная версия или смена состояния может привести к аварии | Отдельный перенос raw access в проверяемые view-типы; проверить жизненный цикл сцены на reconnect, resize, смене Z/device |
| P1 | Клик/прозрачность и визуальная/серверная геометрия иногда расходятся | Игровая матрица тестов для вложенного стекла, открытых дверей, контейнеров и MouseParams; не считать alpha-тест полным покрытием |
| P2 | Общая анимация DMI, особенно конвейеры, не воспроизводится надёжно | Определить нативный источник текущего кадра/времени и проверить off/on/reverse; не анимировать выключенные ленты по совпадающему статическому кадру |
| P2 | `volume.cpp` остаётся крупным и stateful, владение COM в основном ручное, нет доказанной поддержки device loss | Поэтапно выделить ресурсы устройства, scene normalization и geometry builders с игровыми прогонами |
| P2 | Нет полной safe-unload/rollback hooks, глобальные кэши и диагностика могут расти | Документировать запрет горячей выгрузки; разработать управление ресурсами/лимитами и протокол установки/отката |
| P2 | Нет полного аудита лицензий встроенных пикселей для публичного бинарного релиза | Сохранить исходную атрибуцию и проверить исключения ресурсов; публичный source export пока не включает эти данные |
| P3 | Live-inspector зависит от последнего журнала и адресов процесса, debug-пути и старые validation файлы легко перепутать | Явный session/PID format для диагностик; текущие инструменты остаются developer-only |

## Границы этого рефакторинга

Не переписывались управление, физика сервера, методы классификации всей машинерии и порядок D3D-проходов. Не обещается исправление конвейеров, всех стёкол, шкафов и настенных элементов. Вынесение HLSL и hashing не меняет их алгоритмы; исправление `ScreenEdge` — целевое изменение runtime, которое нужно проверить в игре.

Итоговые команды и результаты текущего прохода записываются в `docs/VALIDATION.md`. До ручного прогона новая DLL считается собранной и проверенной локально, а не полностью проверенной в раунде.
